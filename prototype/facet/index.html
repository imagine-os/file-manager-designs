Finding a file by a different attributeYou have to know the folder. A contract filed under a client is not under Legal, and search is the fallback.Rotate to the axis you remember. The same file is under its project, its client and its type at once.
Files that belong to several groupsPick one home. Everything else is a shortcut, a tag or a copy that drifts out of date.Native. A file has a value on each axis, and every face lists it under that value.
Learning curveMinutes. Everyone has used a folder tree; columns just show more of it.An hour. The cube needs one aha moment (three faces, one set), then it is chips and lists.
Keyboard speedExcellent. Arrow keys walk the tree, type-ahead jumps, Space previews. Nothing leaves the list.Good. 1 2 3 snap faces, / searches, arrows nudge. Choosing a face is one keystroke; browsing inside it is a list again.
PredictabilityVery high. The path is the address. It is on screen, in the URL and in every dialog.High once axes are stable. Swapping an axis changes what a face shows, so the chips have to stay visible.
DuplicatesCommon. The same PDF ends up in Clients and Legal, and nobody knows which is current.Structurally unnecessary. One file, several values. The inspector shows every place it appears.
Best forDense archives, well-known structures, people who file as they go, anything a script or a sync client must address by path.Cross-cutting work: client × project × time. Teams that argue about folder names, and anyone who remembers files by a different attribute than the person who filed them.
